# UX-001 — The First 90 Seconds: browser demo

## Entry points

- Production: `https://1998x-stack.github.io/X-Wiki/demo/`
- Local built site: `sites/site/demo/index.html` served with a local HTTP server
- Source: `sites/content/demo/{index.html,demo.css,demo.js}`
- Discovery: X-Wiki homepage links directly to `demo/`

This page is intentionally a self-contained static app. **All example notes
and connections are fictional and hand-authored.** The demo does not transcribe
audio, call an AI model, upload data, request authentication, store state or
send analytics.

## Interaction contract

1. Old idea (August, synthetic).
2. New note (October, synthetic).
3. Connection and explanation.
4. Proposed revision, without mutating the knowledge card.
5. View both evidence excerpts, then unlock Next.
6. Approve or reject; approval updates the knowledge card and revision number.
   Rejection leaves the old node unchanged. Undo restores `pending`, and Start
   over resets the entire flow.

State: `step: 0..5`, `evidenceViewed: boolean`,
`evidenceOpen: boolean`, `decision: pending|approved|rejected`. The DOM
reflects these values using `data-step`, `data-reviewed`, `data-decision`
to support black-box E2E assertions. No background network or browser
storage is used.

## Preview and test

```bash
python scripts/prepare_site.py --strict
python scripts/release_gate.py > sites/.site-docs/release-manifest.json
mkdocs build --strict

npm install --no-save --no-package-lock @playwright/test@1.56.1
npx playwright install chromium
npx playwright test --config tests/e2e/playwright.config.cjs
```

The Playwright test config starts `python3 -m http.server` against the built
`sites/site` output. Tests run in desktop and 390px-wide mobile Chromium.
The Linux Quality and GitHub Pages quality gates install browser dependencies
in CI before executing the same tests.

## Engineering acceptance and evidence

Automated tests validate: entry link, six steps, evidence gate, actual
in-memory revision, rejection, undo/reset, keyboard focus, no external
requests/storage, and narrow-screen layout. Tests are not substitutes
for testing with 15–20 independent first-time users.

The **90-second** benchmark is a user-research target, not a measured claim.
Record user completion time, task abandonment, comprehension, consent and
whether participants independently understand that this is not a live AI
inference. Only then may the product claim success against the onboarding KPI.

## Privacy / security

- `prepare_site.py` copies **only** the three allowlisted static demo
  assets, never the rest of `sites/content` or any `raw/` data.
- Demo story contains no PII and has no user input form.
- Markdown/Git knowledge pipeline is unchanged and not wired to the demo.
- No cookie, localStorage, sessionStorage, microphone, or third-party API.
- Approving a revision does **not** write to Git, SQLite, or the user's data.
- A production interactive workspace will need real evidence permissions
  and authentication before any editing or publishing capability is added.
