## 1. 一句话定位与产品使命

**X-Wiki — Your Second Brain That Evolves.**  
**Talk freely. Turn scattered thoughts into living knowledge.**

X-Wiki 帮助用户将零散记录转化成可追溯、可审阅、可撤销的持续演化知识体系。关键竞争点**不是**“语音转文字”或“AI 摘要”，而是**跨时间发现同一主题的观点变化，并将新证据安全地合并进既有知识**。

### 1.1 JTBD（用户真实需求）

> 当我随手记下一个想法，或隔几周再次谈到同一主题时，我希望系统告诉我它与过去的想法有什么关系、哪些结论应被修正，以及依据是什么；我不想手动管理成百上千份独立笔记，也不希望 AI 代替我修改自己的观点。

### 1.2 核心承诺

- **Capture without friction**：快速记录想法；首访演示无需登录、安装、麦克风授权或导入个人资料。
- **Understand continuity**：识别新内容与既有主题的关联，而不仅生成一篇总结。
- **Evidence before assertion**：建议展示可核对的文本证据、来源标识与时间；无法确定时明确标注。
- **Human-controlled evolution**：任何会修改既有知识的操作需用户确认，支持拒绝、审阅与撤销。
- **Private by default**：原始录音、转写、来源和工作区默认私有；公开分享为显式动作。

### 1.3 目标与非目标

**首发目标**：首次访问者在 ≤90 秒内（目标值，需实测）走完一次“观点发生有证据的改变”的交互体验，理解 X-Wiki 与常见录音笔记产品的差异。证明价值后再投入桌面应用与真实导入体验。

**当前非目标**：团队协作、复杂知识图谱编辑器、全文联网研究、移动原生 App、无授权地读取用户 Voice Memos、伪装成实时 AI 推理、在演示中上传个人录音。

## 2. 谁会使用？用户细分与价值触发

| 用户群 | 触发场景 | 现有替代方案 | 为什么可能选择 X-Wiki |
|---|---|---|---|
| 长期写作者 / 创作者 | 多次记录同一主题，难以整理成演化中的文章 | 笔记/摘要工具 | 持续改写同一组观点并保留证据 |
| 研究人员 / 学习者 | 观点变化、不同资料互相矛盾 | Obsidian/Notion/AI Chat | 显示旧新观点的关系和证据 |
| 创始人 / 独立开发者 | 分散的语音灵感，决策历史难回溯 | Voice Memos + 待办 | 把碎片转成可追踪的决策 |
| 隐私敏感的开发者 | 不愿被绑定到不透明云端笔记 | 本地 Markdown/Git | 文件可导出、可迁移、可审计 |

优先 ICP：已经习惯口述记录且长期反复思考同一主题的**个人用户**。不定位为会议转录套件。

## 3. 产品核心模型

`Source`（音频或文本原始来源，私有）→ `EvidenceSpan`（有位置/时间标记的原文片段）→ `Claim`（从来源提出的主张，允许低可信）→ `KnowledgeNode`（长期概念/决策/项目）→ `ChangeProposal`（新增、修订、冲突或无需更新）→ `Revision`（用户批准的知识版本）→ `Rediscovery`（按需重新展示）。

数据契约：

- 来源片段必须可定位到原始 source ID、偏移或时间；AI 解释与原文引述不得混写。
- ChangeProposal 必须包含 `before`、`after`、`rationale`、`evidence_refs`、`confidence`、`status`。
- `status`：`proposed` → `approved` / `rejected`；批准记录操作者、时间、版本与可逆变更。
- 来源冲突时优先展示对立证据，不自动裁决；任何缺失证据的断言不能作为已验证事实。
- 首发演示为**静态、手工构建的合成数据**；不表示后端已实现上述完整模型。

## 4. UX-001 — The First 90 Seconds（第一优先级）

### 4.1 用户故事

作为第一次访问 X-Wiki 的用户，我想在浏览器里直接体验一个想法如何被新证据更新，而不是先读 README、配置 Python 或创建账户。

### 4.2 必须完成的六步体验

1. **Old Idea / 原有观点**：展示一个过去的知识节点（例如“固定日程提高效率”），附来源日期。
2. **New Note / 新记录**：展示后来另一条记录提出修正（例如“过度僵化可能降低适应性”）。
3. **Connection / 自动关联**：用可视化关系提示说明它们都讨论“每日工作系统”，给出明确关联理由。
4. **Suggested Revision / 修订建议**：用前后对比展示拟更新的知识正文，清晰标记为**建议**而非已保存结果。
5. **Review Evidence / 查看证据**：用户主动打开来源面板，检查新旧原文、标签、日期及结论对应关系。
6. **Approve / 批准或拒绝**：点击批准后 UI 真正更新知识节点，展示已批准状态与撤销动作；拒绝不修改节点。

### 4.3 体验与交互要求

| ID | 需求 | 验收 |
|---|---|---|
| UX001-01 | 访问 `/demo/` 无需登录/安装 | 首屏有明显的“Try interactive demo”与演示数据说明 |
| UX001-02 | 六步渐进式叙事 | 步骤标记、进度提示、上一步/下一步、流程重置 |
| UX001-03 | 可验证的“知识发生变化” | 批准前后节点正文确实不同；拒绝保持原状；撤销恢复原状 |
| UX001-04 | 证据审阅优先 | 批准前用户必须打开过证据；展示来源日期和原句 |
| UX001-05 | 无敏感数据采集 | 不请求网络、麦克风、文件、账户、分析 SDK 或本地存储 |
| UX001-06 | 可访问和手机适配 | 语义 HTML、键盘可操作、焦点可见、状态播报、窄屏布局 |
| UX001-07 | 路径正确 | `/X-Wiki/demo/` 与本地预览资源均正常加载 |
| UX001-08 | 可测量的状态机 | 自动化验证每个步骤、拒绝、批准、撤销、重置、证据门槛 |
| UX001-09 | 可信说明 | 标明“示例/模拟，未使用个人数据、未运行实时模型、无持久化” |
| UX001-10 | 引导到真正产品 | 结束态提供 GitHub / 当前 Wiki 链接以及开源与隐私能力说明 |

### 4.4 状态契约

- `step` 为 `0..5`。不存在无效步骤、不可达阶段和跳跃批准。
- `evidenceViewed` 初始为 `false`，打开证据后转为 `true`。
- `decision` 为 `pending | approved | rejected`。
- 批准必须满足 `step=5` 且 `evidenceViewed=true`；否则操作不执行并显示可理解的错误提示。
- `reset` 清除进度、证据状态与决定；`undo` 恢复 `pending` 和未改动的知识。
- 状态只保存在内存中；刷新页面回到演示起点。无 `localStorage`、`cookies`、外部调用。

### 4.5 视觉与文案

产品第一屏展示价值，而非堆叠技术术语。设计语言：浅色温暖底色、清楚的大标题、可扫描的对比卡片、证据高亮、短句叙事。主 CTA：“Explore an evolving thought”。辅助 CTA：“View the open-source project”。不要使用毫无内容的图谱动效。

## 5. V1.0–V1.3 产品路线

| 阶段 | 用户交付 | 技术依赖 | 出门条件 |
|---|---|---|---|
| UX-001 / V0 展示 | 无安装演示、证据审阅、批准/撤销 | 静态 JS + GitHub Pages；无 API | 真实浏览器 E2E 全绿，首次访客能独立完成 |
| V1.0 导入 | Mac 安装包、文件导入、真实转写、状态反馈 | 本地 Worker、权限向导、打包/签名 | 新用户无需命令行导入一份样本 |
| V1.1 Knowledge Review | ChangeProposal、版本 Diff、用户批注和回滚 | 严格数据契约、来源定位、审阅事务 | 独立证据评测、无未经批准的修改 |
| V1.2 Recall | 带引用问答、主题时间线和按需重新发现 | 检索、内容评级、撤销与用户反馈 | 真实用户愿意再次使用旧知识 |
| V1.3 Launch | 国际化、桌面可靠性、隐私审计、导出 | 签名构建、E2E、隐私策略 | 首批用户留存与安全指标达标 |

## 6. 用户成功指标与独立验收

这些是**目标值，不是现有成绩**，需要测试与实际 Beta 数据。

| 指标 | 发布目标 | 采集方式 |
|---|---|---|
| Time to First Value | 中位 ≤ 90 秒 | 受试者屏幕录制与计时 |
| 演示完成率 | ≥ 70% | 受试者实验（可选择匿名现场记录） |
| 自主理解正确率 | ≥ 80% 能说出“新记录如何修订旧知识” | 访谈盲测 |
| 真实首个知识更新完成率 | ≥ 40%（V1.1） | 经用户同意的产品遥测 |
| 有引用建议的人工支持率 | ≥ 95%（V1.1） | 先冻结黄金集再进行独立标注 |
| 未经授权公开内容 | 0 | 安全审计 + 隐私回归测试 |
| D7 留存 | ≥ 25%（Beta） | 自愿参加的有效队列 |

先开展 15–20 名目标用户的无提示任务测试；优先修复理解偏差、犹豫和中途放弃的环节。自动化功能验收不等于真实用户理解或市场验证。

## 7. 安全、隐私与边界

- 真实音频、原始转写、私有参考来源和 SQLite 状态不可出现在公开 Pages 或前端构建中。
- 当前本地 MLX Whisper 转写不代表所有推理都本地执行：配置的 `pi` 模型提供方可能收到文本。未来需要数据流说明、授权和关闭外发能力。
- 演示为虚构、合成并经明确标注的内容；不使用真实用户日志或私有录音，也不把静态字符串冒充模型实时输出。
- 对不同来源冲突、敏感识别字段、时间不明、无证据结论均要保守提示。
- 发布站点仍遵守既有 Linter、Release Manifest、Pages HTTP 回读、严格 CI 和 Git 审阅机制。

## 8. Product Hunt 定位与准备

- **Name**：X-Wiki
- **Tagline**：Your notes become knowledge that evolves.
- **Demo 的唯一看点**：Old idea → New evidence → Connected insight → Proposed revision → Evidence → Your approval.
- **发布要素**：公开演示 URL、45–60 秒说明视频、真实产品截图、清晰隐私说明、英文首页文案、可读的 README、Maker 回答准备。
- 不承诺“AI 已经懂你”，不以模拟 demo 冒充真实模型；不买票、不索取投票或制造虚假社会证明。

## 10. Definition of Done（产品）

UX-001 仅在下列条件全部满足时完成工程验收：站点可直接进入演示；全六步正确；证据门槛无法绕过；批准/拒绝/撤销状态明确；无外部网络或个人数据采集；无障碍核心操作可用；浏览器 E2E 和既有代码/站点 CI 全绿；Pages 发布回读确认。**用户价值验收必须另用真实用户测试，不因工程 CI 通过而自动宣称完成。**
